## 零、上台之前：有一颗地雷必须先拆

**首页那张混淆矩阵是错的，而且错得会毁掉整场路演。**

`static/validation_confusion_matrix.png` 我打开看了。它的行列标签是 `八段锦0`–`八段锦7`、`五禽戏0`–`五禽戏5`、`其他`，一共 **15 类**，对角线几乎全是 `1.00`。

而 `templates/home.html:315` 给它的 alt 是「ST-GCN **11 类**动作分类模型在验证集上的混淆矩阵」，图注是「11 类动作逐格可核对，这是 Best 权重的训练起点」，所在区块的标题是「**真模型、真推理、真数据**」。

这意味着：任何一个评委在你放首页截图时截屏放大，会同时看到三件事——

1. 你把 A 模型的结果标成了 B 模型的结果；
2. 一条几乎全 1.00 的对角线，本身就是数据泄漏的指纹；
3. 这个项目的真实血统是一个八段锦／五禽戏分类器（`web_app.py:67` 的 `ACTION_CLASSES` 完全对得上，而且默认加载的 `best_model_7_exchange_val_and_test.pth` 就是那份 15 分类权重）。

**而且你们自己的路演纪律第 2 条写的就是「不展示与当前 11 类口径不一致的旧混淆矩阵」。**

处理方式二选一，今晚必须做完：

- **换**：用 `model/mmfit_pose11cls_stride48_best.pth` 重新生成 11 类矩阵；
- **删**：直接删掉这一屏，用一行文字代替「MM-Fit 11 类 · 21 受试者 · 8898 窗口 · 按人划分验证 XX%」。

如果被问到，唯一的过关答法是主动承认血统：「这是历史遗留资产的错误引用，我们的前身是一个八段锦分类项目，我们已经替换。」**主动承认比被当场戳穿好一百倍。**

1. 它**真的能跑**，而且现场可核验；
2. 它**知道自己什么时候不该下结论**（`inconclusive` + 人工复核）；
3. 它想在 ClawHive 上沉淀成**企业自己的资产**。

## 三、逐页设计

### 第 1 页｜封面 · 1500 次

**画面**：首页 Hero 实机截图压暗 60% 做底；正中超大数字 `1500`；下方一行小字 `30 名候选人 × 50 次深蹲 = 今天由 1 名考官用眼睛数完`；右下角品牌与赛道标签。不放团队照片、不放 logo 墙、不放目录页。

**口播（15s / 60 字）**

> 30 个候选人，每人 50 次深蹲，一共 1500 次。今天在工厂招聘现场，这 1500 次是一个考官用眼睛数出来的。我们的项目叫练了么——一个跑在 ClawHive 上的 AI 体能数字员工。

**台上动作**：说完「1500 次」停半秒。全场唯一可以停顿的地方。

### 第 2 页｜痛点 · 第四件事

**画面**：左侧考官图标 → 四个方框 `数次数` `判有效` `登记表` `解释争议`；前三个用灰色，**第四个高亮**。右侧一行大字：`前三件机器能干。第四件，才是我们做这个项目的原因。` 底部灰字合规护身符：`系统输出项目结果；录用决定始终由企业授权人员作出。`

**口播（25s / 100 字）**

> 这个考官同时干四件事：数次数、判断这一下算不算、纸上登记、跟候选人解释为什么不算。前三件事机器能干。第四件事，才是我们做这个项目的原因——因为吵架永远吵在这一件上。我们要替掉的是这四件重复劳动，不是替企业做录用决定。

**台上动作**：「第四件事」重读并停顿。这是全场第一个记忆钩子，也提前挡掉了「AI 招聘歧视」的质疑。

> （标准动作）阶段徽标在毫秒级切换：站立、下蹲、底部、起身。走完完整周期，次数才加一。

### 第 4 页｜核心创新 · 沉淀成企业自己的资产

> ⚠️ **这一页是全稿改动最大的地方，务必按新版讲。**
> 原来的说法是「训练出更好的 Best 权重 → 计数更准」。这条链在代码里不存在：计数和纠错走的是 `src/live_coach.py` 里的几何规则，ST-GCN 权重只在 `mode=="auto"` 时用来识别「这个人在做哪个动作」（`web_app.py:540-553`）。按原版讲，一个懂行的评委一问就穿。
> 新版把它讲成**两件资产**，既是真的，而且是个更好的故事。

**画面**

```
传统 Skill    Markdown 指令 ─→ 调一个已有 API ─→ 结束        资产归属：平台

练了么 Skill  沉淀两件企业资产：
              ① 动作识别 Best 权重   按 tenant + standard + version
              ② 版本化岗位动作标准   阈值 / 阶段模板 / 纠错文案
              每一份结论都带  best_weight_id + rule_version → 可反查
                                                            资产归属：这家企业
```

底部加粗金句：**传统 Skill 编排已有能力；练了么 Skill 让 Agent 训练、沉淀并持续复用一项属于这家企业的垂直能力。**

**口播（48s / 190 字）**

> 但我真正想让各位记住的不是那个画面。
>
> 传统的 ClawHive Skill，是一段 Markdown 加一个固定 API——它编排的是已经存在的能力。练了么想沉淀的是**企业自己的**能力，而且是两件：一件是动作识别的 Best 权重，一件是版本化的岗位动作标准——阈值、阶段模板、纠错文案。
>
> 这里我要说一个刻意的设计：**计数和纠错走的是可解释的几何规则，不是黑盒模型**。因为招聘判定必须能解释给候选人听。一个模型说「你这下不算」，候选人没法申诉；一条「膝角没到阈值」的规则，他可以当场看、当场重做。
>
> 所以企业数据首先提升的是标准，模型化的计数是我们的下一步。每一份结论上都带着权重 ID 和规则版本号，三个月后有人申诉，我们能查到当时用的是哪一版。

**台上动作**：这是拿「创新性」分的地方，语速比其他页慢 10%。「刻意的设计」四个字要说出来——它把一个技术现状变成了一个产品主张。

### 第 5 页｜证据与边界

> ⚠️ **YOLOv8n 从所有材料里删掉。** 我 grep 了全仓库：`yolov8n.pt` 这个 6.5 MB 的文件**没有被任何一行 Python 代码引用**，`requirements.txt` 里也没有 ultralytics。它现在出现在 README 架构表、`SKILL.md §7`、`docs/real-evidence.md` 和首页文案四个地方。这是评委最容易随手验证、也最伤的那种「凑数」。

**画面 · 三宫格（原来的四宫格去掉 YOLOv8n 那格）**

| 位置 | 事实 | 配图 |
|---|---|---|
| 左 | 本地权重：RTMPose ONNX 39.6 MB · ST-GCN 700 KB。全本地推理，不调云端 API | 文件列表截图 |
| 中 | MM-Fit 21 名受试者 · 8898 个 48 帧窗口 · 11 类动作 | 训练曲线 |
| 右 | 23 项自动化测试通过（跑在确定性替身上，不是模型精度证据） | 终端 OK 截图 |

**关于 93.15%，两条路，选一条：**

- **首选（今晚跑得出来）**：重跑一次 **leave-subjects-out**（17 人训练 / 4 人验证），用那个更低的真数字。因为现在 `src/train.py:73` 是 `train_test_split(test_size=0.1, random_state=118)`——**对滑窗做随机划分**，同一个人同一组动作的相邻窗口会同时进训练集和验证集，这是教科书级泄漏；而且 `train.py:117` 的 best 是按 val 选的、没有独立测试集，93.15% 是选模指标不是泛化估计。第 5 轮 Val 93.15% 高于 Train 89.46%，正是泄漏的指纹。
- **备选（来不及重跑）**：干脆不报这个数。说「我们目前的验证划分不是按人分的，所以我们不把它当泛化数字对外」。

**口播（26s / 104 字，按首选路径写）**

> 这些不是 PPT 上的话。权重就在仓库里，全本地推理，不调任何云端 API。训练用的是 MM-Fit 的 21 名受试者、8898 个窗口。
>
> 这里有个数字我要主动说清楚：按窗口随机划分，验证准确率是 93.15%；**按人划分只有 XX%**。我们对外只用后面这个。这个差距恰好说明——通用数据不够用，必须用企业自己的样本训练，**这就是这个 Skill 存在的理由**。

**台上动作**：这是全稿性价比最高的一段。主动交出一个更难看的数字，会让评委相信你其他所有数字；而且它顺手把方法论弱点变成了商业论据。

> 放到 ClawHive 上，它落在五层：模型层是通用模型加企业 Best 权重；知识层把体能标准和 EHS 岗位标准版本化；资产层就是这个 Skill 本身。安全层和连接层我要诚实——输入输出契约已经冻结、有示例、有测试，但**连接器是最后一根线，还没接上**。这也是我等下要提的请求之一。

**台上动作**：黄灯主动指出来。你先说是加分，被问出来是扣分。而且这里埋一句「这也是我等下要提的请求之一」，把 todo 变成第 8 页的 ask。

### 第 7 页｜商业化 + 试点

**画面**：上半两级火箭 —— 第一级「招聘／转岗筛选」按人次或私有化年费；第二级「入职 SOP → 周期复训 → 安全搬运 → 工间恢复」岗位订阅。下半试点盒 `单考场 · 单项目 · 单批次 · 2–4 周 · AI 与人工并行计数`，三个大字指标 `每百人考官工时` `AI／人工计数一致性` `需复核率`。**不放 TAM，不放「降本 70%」。**

**口播（30s / 120 字）**

> 付费入口是招聘和转岗筛选。但我要诚实地说一句：深蹲 50 次是我们跑得通的 Demo 标准，不是我们宣称的行业惯例。真正有强制预算的是**在岗动作 SOP 考核和安全搬运复训**——那里有 EHS 预算、有法定复训周期、有工伤成本。招聘筛选是我们最容易演示的场景，在岗训练是我们真正要卖的场景。
>
> 我们不报「降本百分之七十」，因为我们还没有试点数据。

**台上动作**：这段主动承认「50 次深蹲不是行业惯例」，是为了挡掉一个真会被问穿的问题——`docs/tasks.md` 里 T-034「访谈 5 名招聘负责人」还是 `todo`，`config/posture_standards/recruit_squat_50_v1.json` 的 `source.kind` 写着 `project_owned_engineering_template`、`production_review_required: true`，这个标准是你们自己从代码反推的合成模板。**与其被问出来，不如自己讲成一个更聪明的市场排序。**

## 四、Demo 怎么演

| 方案 | 做法 | 风险 | 建议 |
|---|---|---|---|
| **A · 预录视频** | 提前用**真实模型模式**（`python web_app.py`）录 100 秒，嵌进第 3 页现场配音 | 几乎为零 | **正片默认用这个** |

| C · 固定状态页 | `/coach?ghost_demo=sequence` | 低，但没说服力 | A 失败时兜底 |

**为什么必须录屏**：`docs/acceptance.md` 里 AC-08（真机冷启动 + 摄像头完成 1 次深蹲正确计数）、T-029（演示机 GPU 冷启动与 10 分钟运行）、T-030（光线／机位／遮挡／节奏矩阵）**全部是 todo**。你们从没做过演示机稳定性测试。5 分钟决赛不是赌运气的地方。

**录屏必须用 `python web_app.py` 真实模型模式，不要用 `npm run dev`。** 后者是确定性替身，姿态输入是假的，被发现就完了。

**讲完第 3 页补一句**：

> 这段是预录的，为了保证节奏。如果各位想看现场的，Q&A 我随时可以打开摄像头做五次。

### P1 · 认证接口信任客户端传来的次数

`web_app.py:632` 的 `POST /api/certifications` 没有鉴权、没有 tenant、没有幂等键，**不校验 session_id、不查会话存储**，直接 `int(payload.get('rep_count'))`。任何人 curl 一下就能拿到证书。你整个价值主张是「可解释、可复核的证据」，而证据本身和检测过程没有任何绑定。

**改法约 20 行**：要求携带 `session_id`，服务端从 `live_session_store` 读次数，不接受客户端传值。改完之后台上多一句话可以说：「我们的证书不是页面上的一个数字，是从服务端会话里派生出来的。」

### P1 · 认证记录里是真名

`data/certifications.json` 里有 `leaf`、工号 `1001` 和 `666`。你们自己的规则写着「Demo 一律使用虚构身份」。换成 `演示候选人 / C042`。

### P1 · 四个动作永远数不出来

`src/live_coach.py:425` 的 `_update_rep_count` 开头：非 `SPECIALIZED_EXERCISES` 直接 return。而 `situps`、`tricep_extensions`、`lateral_shoulder_raises`、`jumping_jacks` 都在 `GENERIC_EXERCISES` 里，`_phase_for` 永远返回 `ready`——**这四个动作的计数恒为 0**。

但 `SKILL.md §3` 把 `situps` 明确列为支持动作，输入契约的 `exercise` 枚举也含 `situps`。**如果评委说「演示一下仰卧起坐」，你会返回 0 次，在你们自己的判定矩阵里就是 `not_met`——一个真实候选人会被误判为体能不达标。**

- 最低成本修复：非专项动作的 `rep_count` 返回 `null` 并在界面标注「该动作暂不支持计数」，而不是返回 0。
- 路演对策：**绝口不提这 5 个通用动作可以计数**，Demo 只用深蹲。

### P1 · 真实性证据文档里的训练数据路径已经不存在

文档写着训练集在 `tools/mmfit_pose_11cls_stride48`、原始数据在 `datas/mm-fit.zip`。**这两个路径仓库里都没有。** 评委按文档复现训练，第一步就失败。

### P1 · 语音触发口径全文档写错了

`src/live_coach.py:160-161` 是：

```python
speak_threshold = 2
speak_cooldown_seconds = 5.0
```

也就是**错误连续第 2 次触发语音，同一提示冷却 5 秒**。

而 `SKILL.md:102`、`SKILL.md:270` 和 `docs/练了么-demo分镜口播稿-v3.md` 里至少五处写着「连续 3 次才语音 + 1.5s 冷却」。

**后果**：Demo 里评委是会数的。你说三次，它第二次就响了，当场对不上。而且这个错误写在技能包说明里，那是评审要看的交付物。
**修法**：全部改成「连续第 2 次触发、5 秒冷却」，或者把代码改成 3。**两者对齐哪个都行，但必须对齐。**

### P2 · 心率是编出来的

`web_app.py:251` 的 `estimate_heart_rate` 用像素位移算心率（`base_hr = 70 + min(avg_movement * 500, 50)`），然后在 `web_app.py:279` 以「心率: X BPM」喂给 LLM 生成「心率评估」。**一个用于 HR 决策参考的产品里出现伪造生理指标，是合规炸弹。** 它在 `/upload`、`/webcam-upload` 路径上，评委点得到。把它和所有心率文案从 Demo 路径下线。

### P2 · 无 GPU 模式启动时终端打印「未找到 MM-Fit 健身识别权重」
