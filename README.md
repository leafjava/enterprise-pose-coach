## 三、解决的真实痛点：工厂流水线招聘体能检测

### 业务现状

工厂在招聘流水线员工时，普遍设有**体能达标标准**（如：50 个深蹲 / 100 个俯卧撑 / 30 个仰卧起坐），目的是在入职前筛掉体力不达标的人员，降低后续工伤与流失风险。

### 传统做法的三大痛点

| 痛点 | 具体表现 | 后果 |
|---|---|---|
| **人工成本高** | 需专人盯着每位候选人完成 3 组动作并人工计数、判断是否达标 | 招聘高峰期人力被长期占用，成本随候选人数量线性增长 |
| **标准不统一、易争议** | 人工目测计数存在误差，动作幅度没有客观标准，候选人质疑"我明明做够了" | 纠纷多、入职流程被拖慢 |
| **无留痕、难追溯** | 靠纸质记录或口头确认，事后无法复核"这个人是真的做够了才入职的" | 合规风险，出问题时无法溯源 |

### 我们的解决方案

```
候选人举起手机 / 对准摄像头
        │
        ▼
┌─────────────────────────────────────────┐
│  AI 实时姿态估计（MediaPipe）            │
│  自动识别深蹲 / 俯卧撑 / 仰卧起坐        │
│  逐帧判定动作幅度是否到位 + 自动计数     │
└─────────────────────────────────────────┘
        │
        ▼
   结构化结果输出
   ├─ 每类动作完成次数（50/100/30）
   ├─ 动作到位率 / 姿势错误点列表
   ├─ 达标判定（Pass / Fail）
   └─ 全程视频留痕（可复核、防作弊）
        │
        ▼
  生成《体能达标认证报告》 + 可复核视频证据
```

**核心价值闭环：**

1. **降本** —— 1 个 AI 同时监管多名候选人，无需专人目测，招聘成本大幅下降；
2. **客观** —— 统一动作幅度标准，计数由算法判定，减少人为争议；
3. **留痕** —— 每份达标认证都绑定原始视频，随时可复核，杜绝舞弊与合规风险；
4. **可扩展** —— 达标数据自动沉淀进员工健康档案，入职后无缝衔接职业健康管理。

## 四、核心功能特性

- 🎥 **实时姿态估计** —— 摄像头流 / 视频文件双输入，30 FPS 级别实时分析人体 33 个关键点；
- 🔢 **自动动作计数** —— 深蹲 / 俯卧撑 / 仰卧起坐等动作的起落周期自动识别与计数；
- ✅ **达标判定引擎** —— 支持自定义标准（次数、幅度阈值），输出 Pass / Fail 结构化结果；
- 🧾 **认证报告生成** —— 一键生成《体能达标认证报告》（含视频证据、完成明细、时间戳）；
- 🔊 **实时语音 + 文字纠正** —— 动作不到位时即时提示"膝盖过度内扣，请向外打开"，矫正全程无需人盯人；
- 👥 **批量 / 团队场景** —— 支持多候选人同时检测、数据汇总，生成部门 / 招聘批次汇总报告；
- 🔌 **Agent 可调用** —— 标准化输入输出，可被 ClawHive Agent 编排进招聘、考勤、健康管理等业务流程。

## 五、Skill 标准形态

本 Skill 遵循"可被团队反复调用、可嵌入业务流程、可沉淀为资产"的企业级标准。

### 输入（Input Schema）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `video_input` | 摄像头流 / 视频文件 | ✅ | 候选人动作视频 |
| `exercise_type` | string | ✅ | `squat` / `pushup` / `situp` / `custom` |
| `target_count` | int | ✅ | 达标次数标准（如 50 / 100 / 30） |
| `amplitude_threshold` | float | 可选 | 动作幅度阈值（默认标准值） |
| `candidate_id` | string | 可选 | 候选人标识，用于报告关联 |
| `generate_report` | bool | 可选 | 是否生成认证报告，默认 true |

### 输出（Output Schema）

```json
{
  "exercise_type": "pushup",
  "target_count": 100,
  "completed_count": 100,
  "pass": true,
  "score": 92,
  "amplitude_rate": 0.95,
  "errors": [
    {"type": "elbow_flare", "frames": "00:12-00:14", "suggestion": "肘部内收，靠近身体两侧"}
  ],
  "video_evidence_url": "https://.../candidate_1001_pushup.mp4",
  "report": {"report_id": "R-20260805-001", "url": "https://.../report.pdf"}
}
```

### 被 Agent 调用示例

> 用户：*"帮新候选人王某某做一次入职体能检测，深蹲 50、俯卧撑 100、仰卧起坐 30，达标后生成认证报告。"*

```
Agent 编排：调用 Skill(深蹲) → 调用 Skill(俯卧撑) → 调用 Skill(仰卧起坐)
          → 汇总三个结果 → 判定达标 → 生成《体能达标认证报告》

```

│     结果结构化为 JSON（供 Agent 消费）         │

## 八、稳定性与可复用性保障（占评审 25%，重点打磨）

实时姿态矫正对光线、角度、体型、服装、摄像头质量**非常敏感**，本 Skill 通过以下机制保障稳定性：

### 拍摄规范（内置提示）

- ✅ 全身入镜，侧面朝向摄像头（动作幅度最易判定）；
- ✅ 光线充足、背后无强逆光；
- ✅ 摄像头与身体中心同高，距离 2~3 米；
- ✅ 穿着贴身或宽松适宜的衣服（避免全黑 / 纯白混入背景）。

### 校准流程

1. 进入检测前先展示"站立校准"画面，自动识别身高比例与相机视角；
2. 自动检测关键点置信度，过低时提示调整位置 / 光线；
3. 正式计数前有 3 秒倒计时准备。

### 兼容性覆盖（待测试并文档化）

- 不同身高、体型、性别的识别准确率；
- 侧面 / 斜侧面 / 光线不足场景的表现；
- 长时间使用是否掉帧、误判；
- 器械动作（如哑铃推肩）与徒手动作的判定差异。

### 动作扩展机制

动作判定采用**规则配置 + 关键角度阈值**，新增动作只需新增一份动作定义（起落判据 + 错误判定规则 + 纠正文案），无需改核心引擎 —— 保证可复用、易扩展。
