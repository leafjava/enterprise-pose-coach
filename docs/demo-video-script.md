参考：仓库根目录 [README.md](../README.md)、[PRD](PRD.md)、[tasks](tasks.md)、[real-evidence](real-evidence.md)、[acceptance](acceptance.md)。Demo 种子数据 [enterprise_demo.json](../data/demo/enterprise_demo.json)。

## 3. 招聘深蹲 50 次：当前最强闭环（1:20–3:00）

网页上展示什么：

切到 `/certification`。按顺序展示：

1. 候选人信息录入：姓名 `演示候选人`、工号 `C042`、动作 `深蹲`。
2. 点击"打开摄像头"：浏览器弹权限框，选允许；右上角徽标从 `摄像头未开启` 变为 `摄像头已开启`。
3. 站到画面中间，徽标变成 `手动模式 - 深蹲`，阶段显示 `准备`。
4. 点击"开始训练"，进入实时识别循环。
5. 候选人在摄像头前完成 1 次完整深蹲（下降 → 底部 → 上升 → 站立），次数从 0 跳到 1，阶段在 `准备 / 下降 / 底部 / 上升` 之间循环。
6. 在底部故意屈膝不足、膝盖内扣或躯干前倾，看主提示切换为 `再蹲深一点` / `膝盖与脚尖同向` / `保持胸椎中立`，并听到语音播报。
7. 连续完成 50 次后点击"结束训练"，弹出结构化总结：次数 50、Top 错误、下一重点。
8. 写入认证记录，自动生成 Canvas PNG 证书 `DEMO-CERT-001`，`data/certifications.json` 多一条脱敏记录。

如果现场没有摄像头或 GPU，用 `npm run dev` + `npm run demo`：先用 `/coach` 演示真实页面、API 和规则引擎，再用 `npm run demo` 跑端到端 smoke，输出 `status: passed` 证明 50 次计数闭环可复现。

建议口播：

现在进入 Sample 1：招聘深蹲 50 次体能检测。这是当前最强、最真实的闭环。

打开摄像头后，系统会先用 RTMPose 抽取关键点，再把 48 帧序列喂给 ST-GCN，得到"这是深蹲"还是"这是弓步"的判断。规则引擎对深蹲有专项规则：膝盖是否与脚尖同向、髋关节是否低于膝关节线、躯干前倾角度、上升是否完成。

只有在"准备 → 下降 → 底部 → 上升 → 准备"完整周期走完一次，计数才 +1。如果动作不到位，例如底部蹲得不够深或膝盖内扣，系统只记录错误、扣冷却去抖，但不计数。这确保了"达标"两个字对应的是真实有效的动作次数，而不是任何下蹲都算。

50 次完成后，系统把这次的"动作、次数、Top 错误、规则版本、模型版本、达到状态"写进结构化认证记录，并生成一张 PNG 证书。整个过程没有人去手动数，但每个被算的次数都可以被解释。

评审打点：

- 业务闭环：替代考官逐人计数。
- 技术完整：RTMPose + ST-GCN + 规则引擎全跑通。
- 可解释：每个计数都对应一次完整动作周期，且能说明为什么有动作没被计数。

## 4. 多项目体能组合：模型复用与专项反馈（3:00–4:00）

网页上展示什么：

切到实时健身动作纠错页面。在右侧"训练动作"下拉里依次选择 `弓步`、`俯卧撑`、`肩推`、`划船`、`弯举`。每切换一个动作：

- `弓步`：检测前腿膝关节是否在脚踝正上方、躯干是否过度前倾。
- `俯卧撑`：检测肘部夹角、躯干是否塌陷或拱起。
- `肩推`：检测腕、肘、肩是否在一条垂直线上。
- `划船`：检测肘部是否贴近躯干、是否耸肩。
- `弯举`：检测肘部是否稳定、是否借力。

选完后切到"自动识别"开关，让 ST-GCN 自己挑动作，演示 11 类分类不只是 DeepSquat 这一种。

建议口播：

Sample 2 是多项目体能组合，目的是展示同一套引擎如何服务多种岗位标准。

除了深蹲，练了么对弓步、俯卧撑、肩推、划船和弯举都有专项规则。每次切换动作，规则引擎都会重新加载对应的几何判断，比如俯卧撑看躯干是否成直线、弓步看前膝是否过脚尖、弯举看是否借力。

如果候选人没有选择专项动作，而是希望系统自动识别，可以打开"自动识别"。ST-GCN 会从 11 类动作里挑出最可能的那一类，规则引擎再按那个动作专项规则给出反馈。这就是模型复用：一次训练出来的分类权重，支撑多个招聘项目和企业内训动作。

需要强调的是：其余 5 类动作目前提供的是节奏和稳定性通用反馈，不冒充实测过的专项纠错标准。这是诚实的产品边界。

评审打点：

- 模型复用：一个 ST-GCN，服务多个动作 + 多套岗位标准。
- 能力诚实：通用反馈与专项反馈边界清楚，不假装没做到的能力。
- 业务扩展：从单项目深蹲到多项目组合，匹配企业实际需求。

建议口播：

这是 ClawHive 与本项目的结合方式。

ClawHive 的价值不是再造一个孤立 AI App，而是把个人助手升级为企业可管控、可复用、可审计的数字员工。练了么负责"看懂动作"，ClawHive 负责把这套能力编排进企业流程：HR 在飞书里发起一个"今天 A 批候选人创建深蹲 50 次体能检测"，Agent 读取企业标准 `RECRUIT_SQUAT_50_V1`，校验发起者权限，批量生成检测任务并发送链接，调用我们的视觉 Skill 完成逐帧分析，汇总 pass / not_met / inconclusive，把需复核项通知 HR，最后授权确认后回写招聘台账。

建议口播：

为什么企业愿意为这件事付费？

第一阶段解决的是"招聘高峰考官不够用"和"不同考官尺度不同"。我们不承诺凭空节省 70% 成本，而是帮企业测量：每百人节省考官工时、单次检测成本、计数一致性。这三个数字来自真实试点，不来自 PPT。

第二阶段解决的是"员工入职后如何持续合规地做动作"。复用第一阶段的视觉、规则和审计资产，再叠加上 EHS 岗位标准，就能服务安全搬运复训、工间恢复训练、上岗 SOP 考核。

但我们也很清楚边界在哪里。练了么不替代 HR 做录用决定，不提供医疗诊断，不在没有试点数据时承诺降本比例；实时帧默认不长期保存，技术失败一律进入 `inconclusive` 或人工复核。这就是为什么企业可以放心地把摄像头交给系统——它不会越权，也不会因为算错就冤枉一个候选人。

评审打点：

- 商业可行：四种商业模式对应四类客户。
- 边界清楚：录用、医疗、降本比例都不越权承诺。
- 试点方法：先小范围并行试点，测量真实 ROI，再扩展。

## 风险问题话术

如果评委问"这只是 UI Mock 吧？"：

不是。仓库里 `model/` 有真实权重：`rtmo-*.onnx` 39.6 MB、`mmfit_pose11cls_stride48_best.pth` 700 KB、`yolov8n.pt` 6.5 MB；后端 Flask API 跑的是真实 `LiveCoachEngine`，接收摄像头帧、返回关键点、阶段、计数、纠错。`npm run demo` 在没有 GPU 时是确定性替身，但 `python web_app.py` 跑的是同一套规则和 API。完整证据在 [`docs/real-evidence.md`](real-evidence.md)。

如果评委问"识别率到底多少？"：

我们不报"99% 准确率"这种数字。理由是：真实考场还没有完整标注集，姿势、光线、机位、人体差异都会影响数字。我们能做的是：(1) 给出训练集混淆矩阵；(2) 现场跑同一套真实数据让评委看；(3) 把置信度低的样本交给人工复核。技术失败返回 `inconclusive`，不会因为算错而冤枉候选人。

如果评委问"AI 会不会乱判未达标？"：

不会。三层防线：(1) 模型分类与规则纠错分离；(2) `decision` 必须是 `pass / not_met / needs_retraining / inconclusive` 四种之一；(3) 最终录用由企业授权人员决定，系统只给结论，不替 HR 做决定。`docs/PRD.md` 和 README 都写了这条边界。

如果评委问"Ollama 不装能不能跑？"：

能。Ollama 只是用于生成式教练文案（可选）。视觉分类、规则纠错、计数、认证记录全部不依赖 Ollama。Ollama 不可用时，规则反馈继续工作，只有"AI 教练解释"那段降级显示 Gemma 错误提示。这是核心规则链路和 LLM 增强解耦的好处。

如果评委问"怎么保证候选人不被冤枉？"：

四条：(1) 计数必须经过完整动作周期，幅度不到位只记错误不计数；(2) 关键点无效 → 提示调整站位，不记为未达标；(3) `inconclusive` 永远留给技术故障，HR 可以直接重试；(4) 候选人身份和用途在页面上明示，Demo 一律使用虚构身份。

如果评委问"投资人应该关注什么？"：

关注企业版本化体能/岗位标准、真实场景脱敏错误事件数据、可解释人工复核闭环，以及嵌入 ClawHive 权限和业务系统的连接资产。视觉模型是开源的，壁垒在企业标准和审计能力。商业模式：按检测次数计费、企业私有化部署 + 年费、活跃员工/岗位订阅、ClawHive Skill 调用量结算。

如果评委问"为什么是 ClawHive？"：

因为我们要服务的是企业 HR 和 EHS，不是个人健身用户。HR 已经在飞书/钉钉/企微/OA 里办公，HR 不愿意再开一个新后台。ClawHive 让我们的能力以 Skill 形式进入 HR 已有工作流：HR 发起任务、视觉 Skill 跑分析、结果回写到招聘台账。这是企业级 AI 应用最自然的形态。
