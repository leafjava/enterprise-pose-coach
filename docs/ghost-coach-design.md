# Ghost Coach 视觉纠正场设计与数据审计

## 目标与边界

Ghost Coach 在二维摄像头画面中同时呈现：

1. 员工当前姿势：实线骨架和节点；
2. 同动作、同阶段的目标姿势：半透明虚线骨架；
3. 最多两个优先问题：低频呼吸式方向箭头和短标签。

MVP 只覆盖前视角深蹲。它是二维屏幕引导，不是三维空间测量、医疗建议或工业安全联锁。

## T-039 视觉规范

| 元素 | 规范 |
|---|---|
| 当前骨架 | 4px 实线；稳定绿色、提醒黄色、明显错误红色、低置信度灰色 |
| 当前节点 | 5–7px 实心圆，颜色跟随关节状态 |
| 目标骨架 | 青色、约 70% 透明度、8/7 虚线，不与当前骨架争夺视觉层级 |
| 方向箭头 | 橙色；透明度只在 0.62–0.92 之间缓慢变化，不全亮/全灭 |
| 闪烁频率 | 1.25Hz；系统“减少动态效果”开启时停止脉冲 |
| 提示数量 | 每帧最多两个问题；一个问题可以包含左右两个对称箭头 |
| 出现条件 | 同一错误连续 2 帧后显示 |
| 消失条件 | 错误连续清除 2 帧后隐藏 |
| 降级 | 无人、核心关节置信度不足或对齐失败时隐藏目标和箭头，只给站位提示 |

## T-040 标准姿态数据审计

已检查以下仓库资产：

- `data/standard_*.npy`、`data/reference_*.npy`：对象数组，内部主要是 `(2, 250, 17)` 的既有养生动作序列；
- `config/score_stddata/standard_*.npy`：14 类既有动作的归一化 COCO-17 长序列；
- `config/score_stddata/parsed_data.json`：与上述动作视频关键帧和关节角度对应。

结论：这些资产不是招聘深蹲标准，没有足够的动作语义和授权证据支持将其中某一帧称为“正确深蹲”，因此 Ghost Coach 不直接复用它们。

MVP 选用 `config/posture_standards/recruit_squat_50_v1.json` 中的项目自有工程模板：

- 数据格式：COCO-17，二维归一化坐标；
- 视角：前视角；
- 阶段：`ready/descending/bottom/rising`；
- 来源：根据现有深蹲阶段和几何规则制作的合成模板，无第三方授权限制；
- 限制：只用于黑客松视觉交互演示，生产使用前必须由 EHS/运动专家和目标人群校准。

## 人体比例与画面对齐

- 髋部中心是位置锚点；
- 水平尺度综合肩宽、髋宽和踝宽的中位数；
- 垂直尺度综合躯干、大腿和小腿比例；
- 水平/垂直比例限制在合理范围，防止单帧抖动产生巨大幽灵骨架；
- 支持左右镜像并交换 COCO 左右关节语义；
- 前端按照 `object-fit: cover` 的裁切比例映射归一化关键点，保证 Canvas 与视频对齐。

## 深蹲纠正向量

| 错误代码 | 关节 | 方向 |
|---|---|---|
| `squat_knees_out` | 左右膝 | 分别向画面外侧 |
| `squat_depth` | 髋中心 | 向下 |
| `squat_chest_up` | 肩中心 | 向上并向髋部竖直线靠拢 |

箭头表达修正方向，而不是要求员工把关节精确移动到某个像素。低置信度时不提供方向。

## 验收场景

主视觉场景必须能稳定复现：

```text
膝内扣/躯干前倾
  → 对应关节变红或黄
  → 连续错误后出现目标虚线和方向箭头
  → 员工修正后箭头消失、骨架变绿
  → 完成 bottom → ready 周期，有效次数 +1
```

自动测试验证几何、状态机和 DOM 契约；浏览器 Harness 使用以下地址展示合成姿态并用于截图：

- `/coach?ghost_demo=error`：两类错误、红黄关节和两个方向提示；
- `/coach?ghost_demo=correct`：纠正完成、箭头消失、骨架变绿；
- `/coach?ghost_demo=counted`：回到准备阶段、有效次数 `+1`；
- `/coach?ghost_demo=sequence`：按顺序自动播放以上三态；
- `/certification?ghost_demo=error`：认证流程复用同一视觉纠正场。

2026-08-07 已在本地 Harness 浏览器完成以上页面验收：画布有有效尺寸，视觉层位于视频之上、业务面板之下，DOM 状态与画面一致，控制台无错误。真实模型验收仍需演示机和真人动作，不能用 Harness 替代。

## T-051 其他动作扩展接口

`CorrectionGuideProvider` 把动作错误元数据与方向向量生成从渲染协议中分离；`GhostCoachEngine` 通过版本化配置加载阶段模板，并接受 provider 注入。新增动作需要提供：

1. 版本化 COCO-17 阶段模板与 `phase_aliases`；
2. 错误代码对应的关节、严重程度颜色与短标签；
3. 将当前/目标姿态转换为归一化方向箭头的 provider；
4. 该动作的对齐、方向、置信度和回退测试。

现有测试用 `SAFE_LIFT_DEMO_V1` 临时配置与 `DemoGuideProvider` 验证接口可注入；它只证明扩展机制，不宣称安全搬运动作标准已经完成。

## T-050 可用性测试协议

需要至少 5 名参与者分别完成一次“仅语音/文字提示”和一次“Ghost Coach 视觉提示”的深蹲修正。记录：首次理解时间、修正成功次数、是否看懂箭头、是否感到遮挡或视觉疲劳、对低频脉冲的舒适度。

真实参与者完成前，项目只能把自动动态效果门禁、减少动态效果支持和测试协议标为完成，不能伪造 5 人反馈。记录模板位于 `docs/ghost-coach-usability-results.md`。
