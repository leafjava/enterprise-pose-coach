# 练了么 Demo 分镜口播稿 V2

> 核心主线：传统 Skill 主要编排已有能力；练了么 Skill 通过“首次训练、沉淀 Best 权重、后续持续复用”，帮助 Agent 获得一项可部署、可迭代的垂直教练能力。
>
> 建议成片时长：约 6 分钟。这里的“每一帧”按可执行镜头拆分，不要求逐视频帧讲解。

## 录制前统一用词

- 不说“从零训练一个新的通用大模型”。
- 统一说“在成熟通用模型之上训练任务专用的垂直模型，并沉淀效果最好的 Best 权重”。
- 不把传统 Skill 贬低成“只有 Markdown”。统一说“传统 Skill 主要通过 Markdown 指令或固定 API 编排已有能力”。
- 核心金句：**传统 Skill 编排已有能力；练了么 Skill 帮助 Agent 训练、沉淀并持续调用新的垂直能力。**

## 第二幕：传统 Skill 与练了么 Skill 的区别（0:30–1:20）

### 镜头 4｜传统 Skill（0:30–0:47）

**画面**

- 切到一张左右对比图或 README 中对应说明。
- 左侧标题显示“传统 Skill”。
- 左侧流程显示：`Agent → Markdown 指令 / 固定 API → 返回结果`。
- 鼠标顺着箭头从左向右移动。

**口播**

传统 Skill 通常通过 Markdown 指令告诉 Agent 应该怎样完成任务，或者让 Agent 调用一个已经固定好的 API。它主要解决的是已有能力的描述、调用和编排问题。

### 镜头 5｜练了么 Skill（0:47–1:02）

**画面**

- 对比图右侧亮起，标题显示“练了么 Skill”。
- 显示流程：`首次调用 → 获取数据 → 训练垂直模型 → 选择 Best 权重 → 本地沉淀`。

**口播**

练了么 Skill 不止调用一个固定能力。当 Agent 第一次使用它时，Skill 会带着 Agent 完成数据获取、模型训练、效果评估和最优权重选择，形成一个面向动作教练任务的垂直模型。

### 镜头 6｜第一次与以后每一次（1:02–1:20）

**画面**

- 对比图切换成上下两条链路。
- 上方显示“第一次使用：训练并保存 Best 权重”。
- 下方显示“后续使用：直接加载 Best 权重”。
- 最后将“Best 权重”节点高亮。

**口播**

第一次调用负责训练和沉淀；以后每一次调用，都可以直接加载已经训练好的 Best 权重，不需要从头再来。

所以我们的核心区别是：传统 Skill 主要编排已有能力；练了么 Skill 帮助 Agent 训练、沉淀并持续调用一项新的垂直能力。

## 第三幕：第一次调用如何训练能力（1:20–2:30）

### 镜头 7｜Agent 接收目标（1:20–1:32）

**画面**

- 打开 `skill-build/enterprise-pose-coach/SKILL.md`。
- 停在首次初始化或训练流程说明处。
- 画面侧边可叠加示例任务：“为企业深蹲考核建立动作教练能力”。

**口播**

我们来看第一次调用。企业可以告诉 Agent：我需要一个能够完成深蹲识别、计数和纠错的教练能力。

### 镜头 8｜获取开源数据（1:32–1:47）

**画面**

- 切到数据准备页面、终端日志或流程图。
- 画面显示“检索候选数据集、检查许可证、筛选动作类别、下载或接入”。
- 展示 MM-Fit 数据集名称。

**口播**

Skill 首先指导 Agent 搜索并筛选适合任务的开源数据集，同时检查数据许可、动作类别和数据格式。当前演示使用 MM-Fit，它包含 21 名受试者和 8898 个真实人体动作窗口。

### 镜头 9｜数据处理链路（1:47–1:59）

**画面**

- 展示数据从原始样本到训练窗口的流转图。
- 依次高亮“清洗、关键点转换、48 帧切窗、训练集与验证集划分”。
- 显示数据形状 `(8898, 2, 48, 17)`。

**口播**

接下来，Agent 按照我们设计好的链路完成数据清洗、人体关键点转换、48 帧序列切分，以及训练集和验证集划分。这里不是让 Agent 临时发挥，而是严格执行 Skill 定义的训练流程。

### 镜头 10｜训练垂直模型（1:59–2:12）

**画面**

- 切到训练终端或训练曲线。
- 展示 ST-GCN 训练过程、epoch、训练损失和验证指标。
- 同时在角落显示“通用模型能力 + 垂直任务数据”。

**口播**

然后，Agent 以成熟模型为起点，使用任务数据训练面向动作分类的垂直模型。RTMPose 负责提取人体关键点，ST-GCN 学习连续动作序列，规则引擎负责动作阶段、计数和几何纠错。

### 镜头 11｜选择并保存 Best 权重（2:12–2:30）

**画面**

- 展示验证指标比较或多个 checkpoint。
- 鼠标从多个权重移动到 `best` 文件。
- 打开 `model/` 目录，重点框选 `mmfit_pose11cls_stride48_best.pth`。
- 在旁边显示“保存模型版本、数据版本、评估结果和适用动作”。

**口播**

训练过程中会产生多个 checkpoint。系统不是简单保留最后一次训练结果，而是根据验证集表现选择效果最好的 Best 权重，并一起记录数据版本、模型版本、评估结果和适用动作。

这个 Best 权重，就是第一次使用 Skill 后，为 Agent 沉淀下来的垂直能力资产。

## 第五幕：后续调用直接复用 Best 权重（2:58–3:22）

- 随后转场进入 `/certification`。

**口播**

此时，动作识别、实时计数和实时纠错，就不再只是应用里写死的功能，而是 Agent 可以随时调用的一组垂直教练能力。下面我们直接看它如何工作。

## 第六幕：实时深蹲教练 Demo（3:22–4:38）

### 镜头 16｜录入演示身份（3:22–3:31）

**画面**

- 在 `/certification` 输入“演示候选人”和工号 `C042`。
- 动作选择“深蹲”。
- 不展示任何真实个人信息。

**口播**

这里以企业招聘中的深蹲考核为例。我们录入虚构候选人信息，并选择深蹲项目。

### 镜头 17｜打开摄像头（3:31–3:42）

**画面**

- 点击“打开摄像头”并允许权限。
- 等待状态从“摄像头未开启”变成“摄像头已开启”。
- 人站到画面中央，等阶段显示“准备”。

**口播**

摄像头开启后，每一帧画面都会进入本地推理链路。RTMPose 提取关键点，Best 权重识别连续动作，规则引擎判断动作阶段和完成质量。

### 镜头 18｜完成一次标准动作（3:42–3:58）

**画面**

- 点击“开始训练”。
- 完成一次标准深蹲。
- 画面完整看到“准备、下降、底部、上升、准备”的阶段变化。
- 次数从 0 变成 1 时停一秒。

**口播**

现在完成一次标准深蹲。系统会实时识别“准备、下降、底部、上升、再回到准备”的完整周期。只有完整周期成立，次数才会加一。

### 镜头 19｜故意做错并即时纠正（3:58–4:17）

**画面**

- 故意做一次深度不足的深蹲。
- 让画面明确出现“再蹲深一点”。
- 保留语音播报。
- 展示这次错误动作没有增加计数。
- 可再故意膝盖内扣，出现“膝盖与脚尖同向”。

**口播**

这一次我们故意没有蹲到位。提示会在动作发生的当下变成“再蹲深一点”，并同步进行语音播报。因为动作不完整，这次只记录错误，不计数。

如果出现膝盖内扣，系统也会立刻提示“膝盖与脚尖同向”。这就是实时监测、实时纠错和实时计数三个层面的同时成立。

### 镜头 20｜训练结果与证书（4:17–4:38）

**画面**

- 切换到已完成 50 次的演示状态。
- 点击“结束训练”。
- 展示次数、Top 错误、下一步训练重点、模型版本和规则版本。
- 展示认证结果和 Canvas PNG 证书。

**口播**

完成 50 次后，系统会生成结构化结果，记录有效次数、Top 错误、下一步重点、规则版本和本次调用的模型权重版本，并生成认证凭证。

整个过程不需要考官人工计数，而且每一个结果都可以追溯到具体的模型版本和动作规则。

## 第七幕：一个 Best 权重支撑多种教练能力（4:38–5:05）

### 镜头 21｜多动作切换（4:38–4:53）

**画面**

- 进入 `/coach`。
- 快速切换深蹲、弓步、俯卧撑、肩推、划船和弯举。
- 每种动作停留一至两秒，展示对应反馈。
- 最后切到自动识别模式。

**口播**

同一个垂直模型还可以支撑多种教练任务。目前系统对深蹲、弓步、俯卧撑、肩推、划船和弯举提供专项纠错规则，并能够从 11 类动作中自动识别当前动作。

### 镜头 22｜能力边界（4:53–5:05）

**画面**

- 页面保持自动识别状态。
- 画面叠字：“6 类专项纠错；其余类别提供通用节奏与稳定性反馈”。

**口播**

我们也明确能力边界：六类动作提供专项几何纠错，其余动作目前只提供节奏和稳定性的通用反馈，不会把尚未验证的规则包装成成熟能力。

## 第八幕：下载、私有部署与持续进化（5:05–5:35）

### 镜头 23｜下载安装到本地（5:05–5:18）

**画面**

- 展示 Skill 目录、模型目录和启动命令。
- 流程图显示“下载 Skill → 本地初始化 → 加载 Best 权重 → Agent 调用”。

**口播**

用户可以把练了么 Skill 下载到自己的电脑，也可以部署在企业私有环境。安装完成后，用户自己的 Agent 就能够加载 Best 权重，直接执行健身教练、体能训练和动作考核任务。

### 镜头 24｜持续迭代（5:18–5:35）

**画面**

- 展示循环图：`新数据 → 再训练 → 评估 → 新 Best 权重 → 版本升级`。
- 注意让“旧版本可回滚”和“新版本通过评估后替换”出现在画面中。

**口播**

当企业未来积累了经过授权和脱敏的新样本，还可以再次运行训练链路。只有当新权重通过评估并优于当前版本时，才升级为新的 Best 权重；旧版本仍然保留，可以审计，也可以回滚。

因此，这项垂直能力不是一次性的，它能够随着数据和业务标准持续进化。

## 第九幕：ClawHive 编排与安全边界（5:35–5:55）

### 镜头 25｜Agent 工作流（5:35–5:46）

**画面**

- 展示流程：`HR 发起任务 → Agent 调用练了么 Skill → 加载企业 Best 权重 → 实时检测 → HR 复核 → 回写台账`。

**口播**

进入企业流程后，HR 只需要在现有工作入口发起任务。Agent 调用练了么 Skill，加载该企业的 Best 权重，完成实时检测，再把需要复核的结果交给 HR，授权后回写业务台账。

### 镜头 26｜隐私和决策边界（5:46–5:55）

**画面**

- 显示四个标签：`本地推理`、`原始帧默认不长期保存`、`低置信度进入复核`、`最终决定由授权人员作出`。

**口播**

原始视频帧默认不长期保存；低置信度、遮挡或技术失败统一进入 `inconclusive` 和人工复核；最终录用决定始终由企业授权人员作出。

## 建议制作的关键示意图

为保证评委一眼看懂，建议至少制作下面三张简单动画或静态图：

### 示意图 A：传统 Skill 与练了么 Skill

```text
传统 Skill
Agent → Markdown 指令 / 固定 API → 调用已有能力 → 返回结果

练了么 Skill
Agent → 数据获取 → 训练垂直模型 → 评估 → Best 权重 → 持续调用
```

### 示意图 B：第一次与后续调用

```text
第一次调用
任务目标 → 开源数据集 → 数据处理 → 模型训练 → 评估 → 保存 Best 权重

后续调用
教练任务 → 加载 Best 权重 → 动作识别 → 实时计数 → 实时纠错
```

### 示意图 C：持续升级

```text
当前 Best 权重
       ↓
新增授权数据 → 再训练 → 新旧权重评估
                         ↓
              更优才升级，否则保留当前版本
```

## 现场展示失败时的备用口播

如果训练日志无法现场运行，可以打开已经保存的训练证据并说：

> 为了保证 Demo 时间可控，我们没有在现场重新等待完整训练，而是展示同一条训练链路已经产出的数据统计、训练日志、评估结果和 Best 权重。现场实时教练使用的正是这个权重，不是 Mock 返回值。

如果摄像头或 GPU 临时不可用，可以切换确定性演示链路并说：

> 当前使用的是无摄像头的确定性姿态输入，但页面、API、动作状态机、计数规则和 Best 权重加载链路与真实模式一致。它只替代现场摄像头输入，不替代核心推理和业务闭环。
