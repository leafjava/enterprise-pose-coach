# 练了么 Demo 分镜口播稿 V3（帝王蟹 ClawHive 企业级 Skill 大赛版）

> **赛事定位**：网易智企帝王蟹 ClawHive "超级个体" 企业级 Skill 大赛。评委在找的不是花哨应用，而是"**个人助手升级为企业可管控、可复用、可审计的数字员工**"的资产化能力。
>
> **主线一句话**：传统 ClawHive Skill 编排已有能力；**练了么 Skill** 自带 **训练 + 沉淀 + 复用** 生命周期，把"通用视觉模型"升级成"**企业专属垂直教练资产**"——**监测是实时的，纠错是实时的，计数是实时的，反馈也是实时的**。
>
> **时长目标**：约 6 分钟（10 幕 + 录制前检查 + 5 分钟压缩版 + 评委问答兜底）。
>
> **帝王蟹五层能力对照**（脚本始终对齐）：
> 1. **模型层** —— 成熟通用模型（RTMPose + ST-GCN + YOLOv8n）+ 训练出来的垂直模型（Best 权重）；ClawHive 调度；实测推理性能稳定。
> 2. **连接层** —— 飞书 / 钉钉 / 企微 / OA 发起检测，向招聘台账回写结果；Agent 调用 Skill 由 ClawHive 完成。
> 3. **安全层** —— 等保三级 + ISO27001；租户权限隔离、最小数据回传、人工复核、全链路审计；原始帧默认不长期保存。
> 4. **知识层** —— 企业版本化招聘体能标准与 EHS 岗位标准作为 Skill 训练输入；Best 权重命名按 `tenant + standard + version`。
> 5. **资产层** —— 单 Skill（**enterprise-pose-coach**），自带 训练 + 沉淀 + 复用 生命周期；可下载、可私有部署、可重复调用、可持续进化（旧版可回滚）。

- 不说"从零训练一个新的通用大模型"——统一说"在成熟通用模型之上训练任务专用的垂直模型，并沉淀效果最好的 Best 权重"。
- 不把传统 Skill 贬低成"只有 Markdown"——统一说"传统 Skill 主要通过 Markdown 指令或固定 API 编排已有能力"。

- **辅助金句（必说三次）**：**监测是实时的，纠错是实时的，计数是实时的，反馈也是实时的**。

## 附录 A：评委问答备答（10 题）

> 全部用"先正面回应问题，再给落地证据"的方式回答。回答一律不超过 90 秒。

### A1. 训练真的跑过吗？
> 跑过。我们训练数据来源是 MM-Fit 公开数据集（21 名受试者 / 8898 个训练窗口 / shape `(8898, 2, 48, 17)`），训练曲线、混淆矩阵、RTX 5070 Ti 推理日志都保存在 `docs/real-evidence.md` 和 `docs/mmfit-retrain-summary-2026-05-29.md`。这不是为演示造出来的 Mock，是真实跑过且可复现的证据。

### A2. 为什么不用一个固定 API 解决？
> 一个固定 API 解决的是"已有能力的描述、调用、编排"。企业的新问题，比如这家工厂的深蹲标准、那家仓储公司的俯卧撑定义，公开 API 没现成答案。练了么 Skill 不是替 API，是让 Agent 在企业私域数据上**自己训出**垂直能力。

### A3. 实时四层不是营销词吗？
> 不是。我们当场把它们画在同一个画面上：监测来自摄像头每帧（毫秒级阶段徽标切换），纠正来自规则引擎（错误连续 3 次才语音 + 1.5s 冷却），计数来自完整动作周期（幅度不足不计数），反馈来自会话事件流（完成一次完整动作就刷新一次 Top 错误统计）。每条实时都有自己的输入来源，不是同一根数据说四遍。

### A4. 摄像头画面会上云吗？
> 不会。实时帧默认不长期保存，不把原始人像发送给生成式大模型；本地加载 Best 权重做实时推理。如果未来需要保存证据，必须有明确告知、访问权限、用途和到期删除策略——这一条写在 README 的"数据、安全与使用边界"里。

### A5. AI 漏数 / 误数怎么办？
> 我们的错误返回状态是四态：pass / not_met / needs_retraining / inconclusive。无人入镜、遮挡、模型超时、置信度不足一律返回 `inconclusive`，进入人工复核，不能伪造成 `not_met`。最终录用由企业授权人员结合完整信息决定，不存在"AI 一票否决"。

### A6. 一家工厂和另一家工厂的最佳权重会冲突吗？
> 不会。Best 权重按租户命名空间隔离，命名规则是 `bw_<tenant>_<date>_<version>.pth`，每家工厂的权重独立下载、独立部署、独立调用、可重复调用、可再训练升级（旧版本保留可回滚）。

### A7. 对帝王蟹 ClawHive 平台的契合度？
> ClawHive 给企业带来模型、连接、安全、知识和资产五层打通。练了么 Skill 不是一个孤立 App，它直接落到这五层里：模型层走成熟通用模型 + Best 权重的双层资产；连接层在飞书、钉钉、企微、OA 里发起检测、回写结果；安全层提供租户权限、最小数据回传、人工复核、全链路审计；知识层把企业体能标准和 EHS 岗位标准版本化；资产层就是单 Skill 自带训练流程 + 沉淀 Best 权重。

### A8. 商业上凭什么赚钱？
> 商业上准备了四种模式：按检测次数计费、企业私有化部署 + 年费、活跃员工订阅、上架企业技能市场后的平台分发。在没有试点数据之前，我们不承诺具体百分比，只承诺和试点一起测量"每百人节省考官工时 / 单次检测成本 / 计数一致性"三项指标。

### A9. 你和市面上的姿态识别 SaaS 有什么不一样？
> 市面上的姿态识别 SaaS 给的是"已有 API"。练了么 Skill 给的是"训练链路 + 沉淀 + 复用"三件套——一家工厂招聘标准改了，过去要重新集成新 SaaS；用我们的 Skill，Agent 直接进入训练链路，在已有数据上训练新 Best 权重，无需换产品。这是 ClawHive 资产层的真正含义。

### A10. 48 小时 MVP 还能加什么？
> 48 小时 MVP 集中做一件事：让 ClawHive 从飞书或 OA 发起一个"深蹲 50 次"检测任务，跑通"任务创建 → 候选人完成 → 结果通知 HR"闭环，并把 best_weight_id 写进回调体。其它 4 条 P0（多项目标准、EHS 复训、租户权限、审计）已经在 PRD/tasks.md 排好。

## 附录 B：现场失败兜底口播（如果 Demo 崩了）

### B1. 摄像头拒绝 / 浏览器没有摄像头

> 评委好，我们用的是真实浏览器摄像头链路，没有摄像头就会拒绝。这是我们要演示的边界之一：缺摄像头就不出结果，绝不会偷偷换视频。如果你们允许，我直接切到 `/coach?ghost_demo=sequence` 这个无摄像头入口，用确定性姿态输入跑一遍实时监测 + 实时纠正 + 实时计数。

### B2. 模型推理超时 / GPU 抢占

> 我们当前在做 6 类专项规则 + 5 类通用反馈的演示；如果 GPU 推理被抢占，**前三项实时层仍然会工作**：监测是规则引擎驱动的，纠错是规则 + 错误去抖 + 语音冷却，计数是完整动作周期。即使 ST-GCN 推理变慢，反馈层会立刻把当前帧标 `inconclusive`，让候选人重试，而不是返回错误结论。

### B3. 训练证据打开失败

> 我现场展示的是 `docs/real-evidence.md` 和 `docs/mmfit-retrain-summary-2026-05-29.md`，里面有 MM-Fit 数据统计、混淆矩阵、RTX 5070 Ti 推理日志。如果打开失败，我可以直接打开 `model/` 目录，四个权重文件大小（39.6 MB / 700 KB / 1.2 MB / 6.5 MB）已经在 README 里列过，文件本身在仓库里就是证据。

### B4. Ollama / 生成式反馈不可用

> 我们生成式反馈是可选依赖。Ollama/Gemma 不可用时，视觉分类和规则纠错仍可运行，只有生成式教练文案会降级。这是一个明确的能力边界——核心规则判断不依赖任何生成式大模型。

### B5. ClawHive 端任务创建演示失败

> 48 小时 MVP 范围内 ClawHive 连接器尚未完成。但我可以演示**目标形态**——本地用 `request_id + tenant_id + standard_id + best_weight_id` 发起一次 Skill 调用，回传结构化 `decision / valid_rep_count / top_errors / model_version / best_weight_id`。这是 Skill 上架后的标准输入输出契约，证明我们已经在为 ClawHive 接入做铺垫。

### B6. 评委要求"再演一次实时纠错"

> 好的，我会再做一次同款下蹲，故意做膝盖内扣和胸口前倾两个错误。第一次错误只显示在画面顶部不播音，第三次错误才触发语音。同一提示会冷却 1.5 秒。这一套机制就是为"避免语音轰炸"设计的。
