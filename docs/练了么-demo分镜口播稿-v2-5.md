# 练了么 Demo 分镜口播稿 V2.5（基于 README 完整版）

> **核心主线**：传统 Skill 主要编排已有能力；练了么 Skill 通过"**首次训练、沉淀 Best 权重、后续持续复用**"，帮助 Agent 获得一项可部署、可迭代、可审计的垂直教练能力。
>
> **时长目标**：约 6 分钟（10 幕 + 1 幕问答兜底）；可压缩到 3 分钟的"快速演示版"见附录 B。
>
> **叙事承诺（评委看到 / 听到必须命中）**：
> 1. **真模型**：RTMPose 39.6 MB + ST-GCN 700 KB + YOLOv8n 6.5 MB，本地权重，不再是 Mock。
> 2. **真训练**：MM-Fit 21 受试者、8898 个 `(48, 17)` 窗口，最佳验证 0.94，Best 权重 sha256 可核验。
> 3. **真沉淀**：按 `tenant + standard_id + version` 命名的 `.pth` 文件，沉淀到企业私有环境。
> 4. **真复用**：Best 权重加载日志可见，��秒级实时监测 + 即时语音 + 完整周期计数同步成立。
> 5. **真边界**：低置信度 / 关键点无效 / 模型超时一律返回 `inconclusive` 进入复核，不伪造 `not_met`。

## 录制前统一用词（避免"行话掉分"）

- 不说"从零训练一个新的通用大模型"——统一说"在成熟通用模型之上训练任务专用的垂直模型，并沉淀效果最好的 Best 权重"。
- 不把传统 Skill 贬低成"只有 Markdown"——统一说"传统 Skill 主要通过 Markdown 指令或固定 API 编排已有能力"。
- 不说"AI 替 HR 做决定"——统一说"AI 输出达标状态供 HR / EHS 复核，最终录用由企业授权人员结合完整信息决定"。
- 核心金句：**传统 Skill 编排已有能力；练了么 Skill 帮助 Agent 训练、沉淀并持续调用新的垂直能力。**
- 辅助金句：**一个 Skill 贯穿"训练 + 沉淀 + 复用"，一个权重贯穿"招聘筛选—上岗训练—在岗复训"。**

**口播**
> 练了么：一个跑在 ClawHive 上的 AI 体能数字员工 Skill。它不是固定推理 API，而是自带"训练 + 沉淀 + 复用"生命周期的单 Skill——首次调用训练任务专用垂直模型并沉淀 Best 权重，后续每一次调用都直接加载这个 Best 权重。

### 镜头 2｜三个"实时" + 三个证据 chip（0:08–0:22）

**画面**
- 鼠标依次指向 Hero 区三个 proof chip，每点一个停留一秒：
  1. **训练 + 沉淀 + 复用** —— 首次调用训练垂直模型 → 沉淀 Best 权重 → 后续调用直接复用
  2. **实时四层** —— 实时监测（毫秒级阶段切换）+ 实时纠正（即时语音）+ 实时计数（完整周期）+ 实时反馈
  3. **ClawHive 单 Skill** —— 练了么 Skill 自带训练 + 沉淀 + 复用 生命周期，HR 在飞书 / 钉钉 / 企微 / OA 直接调用

**口播**
> 这个 Skill 有三个"实时"——监测是实时的、纠错是实时的、计数是实时的。它不是事后总结报告，是当下反馈。它跑在通用模型 + 训练出来的 Best 权重之上，由 ClawHive Agent 在企业现有 IM 里直接调用。

## 第二幕：传统 Skill 与练了么 Skill 的区别（0:30–1:20）

**目标**：用一张左右对比表把"传统 Skill 调用什么 vs 练了么 Skill 调用什么"压成 30 秒。

### 镜头 4｜传统 Skill 的本质（0:30–0:47）

**画面**
- 切到 README § "这是一个传统 Skill" 一节的对比表（或自制的左右对比图）。
- 左侧标题"传统 Skill"，流程：`Agent → Markdown 指令 / 固定 API → 调用已有能力 → 返回结果`。

**口播**
> 传统 Skill 通常通过 Markdown 指令告诉 Agent 应该怎样完成任务，或者让 Agent 调用一个已经固定好的 API。它主要解决的是已有能力的描述、调用和编排问题——比如查天气、查订单、生成日报。

### 镜头 5｜练了么 Skill 的本质（0:47–1:04）

**画面**
- 对比图右侧亮起，标题"练了么 Skill"，流程：
  `首次调用 → 数据获取 → 数据处理 → 模型训练 → 评估 → Best 权重 → 沉淀`
  `后续调用 → 加载 Best 权重 → 动作识别 → 实时计数 → 实时纠错`

**口播**
> 练了么 Skill 不止调用一个固定能力。当 Agent 第一次使用它时，Skill 带着 Agent 完成数据获取、模型训练、效果评估和最优权重选择，形成一个面向动作教练任务的垂直模型。

### 镜头 6｜资产归属对比 + 核心金句（1:04–1:20）

**画面**
- 表格下半部分对比四项核心维度（建议 4 行 4 列，停留一秒）：

  | 维度 | 传统 Skill | 练了么 Skill |
  |---|---|---|
  | 能力来源 | 已有 API / Markdown | 训练沉淀的 Best 权重 |
  | 是否带训练流程 | 否 | 是（首次调用自动跑） |
  | 能否跨企业升级 | 否 | 是（积累新样本即可再训练） |

- 结尾大号字：**核心金句**——传统 Skill 编排已有能力；练了么 Skill 帮助 Agent 训练、沉淀并持续调用新的垂直能力。

**口播**
> 关键区别有四点：能力来源不同、有没有训练流程、能否跨企业升级、资产归谁。我们用一个核心金句总结——传统 Skill 编排已有能力；练了么 Skill 帮助 Agent 训练、沉淀并持续调用新的垂直能力。

## 附录 A：评委问答备答（10 题高频兜底）

> 评委提问时不必切镜头，按以下口径直接回答即可。

### Q1：传统 Skill 也能接视觉模型 API，为什么还需要"训练 + 沉淀"？

答：传统 Skill 调用的是一个**固定 API**——它能解决"看见动作"的问题，但**不能针对企业的特定岗位标准沉淀能力**。练了么 Skill 的差异不在于"能不能识别动作"，而在于**第一次调用就帮 Agent 训练出企业专属的 Best 权重并沉淀**，新样本进来后还能再次训练升级。这是资产归属与可成长性的差别。

### Q2：MM-Fit 只有 21 个受试者，够不够？

答：够覆盖演示与 MVP；通用模型权重是公开的，我们用 21 个受试者 + 8898 个窗口训练出 Best 权重只是演示链路。生产场景的真实数据来自企业**自己的脱敏样本**，而不是 MM-Fit；MM-Fit 的价值在于提供一个**可复现的训练起点与回归基线**。

### Q3：训练一次要多久？需要 GPU 吗？

答：在 RTX 5070 Ti Laptop GPU 上，MM-Fit 微调到收敛约几十分钟；企业样本量增加后通常在数小时量级。Skill 内置 CPU 推理路径（`npm run dev`），无 CUDA 也能跑主流程。

### Q4：Best 权重存在哪里？怎么保证不外泄？

答：Best 权重按 `model/bw_<tenant>_<date>_<version>.pth` 沉淀在企业私有推理环境，租户命名空间隔离。Skill 包的 `permissions.best_weight_artifact_download = tenant-scoped` 显式限定下载范围；旧版本保留可回滚，审计事件通过 `audit.emit` 落库。

### Q5：HR 凭什么相信 AI 的计数？

答：因为每个结论都带四件事——`decision`（pass / not_met / needs_retraining / inconclusive）、`valid_rep_count` / `invalid_rep_count`、`top_errors` 倒序最多 3 条、`best_weight_id` + `best_weight_version`。任何一个数字都能反查到当时的规则版本和权重版本。低置信度、关键点无效、模型超时一律返回 `inconclusive` 进人工复核，不伪装成 `not_met`。

### Q6：会不会替代 HR？

答：不替代。AI 输出"达标 / 未达标 / 需复核"的状态供 HR / EHS 复核，最终录用、辞退、绩效、薪酬都由企业授权人员结合完整信息决定。系统也不提供医疗诊断、康复处方、伤病预测。

### Q7：摄像头数据会不会泄露？

答：实时帧默认不长期保存，不上传给任何外部生成式大模型。需要保存视频证据时必须有明确告知、访问权限、用途和到期删除策略。原始摄像头帧上传到生成式大模型（`raw_frame_upload_to_llm`）在 `permissions` 中显式 `denied`。

### Q8：未来怎么赚钱？

答：四种商业模式可以组合——按检测次数计费（适合招聘旺季）、企业私有化部署 + 年费（数据敏感的大客户）、活跃员工 / 岗位订阅（在岗训练扩张）、ClawHive Skill 调用结算（平台上架后）。不在没有试点数据时承诺"成本下降 70%"或"工伤下降 50%"。

### Q9：为什么只做深蹲，不能做搬运？

答：深蹲是屈髋屈膝搬运的代理动作，6 类专项纠错覆盖了深蹲、弓步、俯卧撑、肩推、划船、弯举；工业搬运的真正 SOP 规则仍需企业 EHS 专家基于真实场景校准。Sample 3 在 README 中明确"代理动作 + 实时反馈 + 会话总结"，不把尚未校准的工业基座伪装成已完成能力。

### Q10：你们的壁垒在哪里？

答：长期壁垒不是某一个开源姿态模型，而是——企业版本化体能 / 岗位标准、真实场景的脱敏错误事件数据、可解释的人工复核闭环，以及嵌入 ClawHive 权限和业务系统的连接资产。

## 附录 C：现场失败兜底口播

### C-1：训练日志无法现场跑

> 为了保证 Demo 时间可控，我们没有现场等待完整训练，而是展示同一条训练链路已经产出的数据统计、训练日志、评估结果和 Best 权重。现场实时教练使用的正是这个权重，不是 Mock 返回值。

### C-2：摄像头或 GPU 临时不可用

> 当前切换到无摄像头的确定性姿态输入，但页面、API、动作状态机、计数规则和 Best 权重加载链路与真实模式一致。它只替代现场摄像头输入，不替代核心推理和业务闭环。

### C-3：ClawHive 真实接入尚未完成

> ClawHive 完整连接器是 48 小时 MVP 的下一步——任务创建、批次通知、招聘台账回写。当前 demo 用本地 Flask API 完整模拟 ClawHive Agent 调用 Skill 的两条路径（首次训练 + 后续复用），契约字段与 Skill 包对齐。

### C-4：评委质疑"为什么不直接调 API"

> 调 API 调用的是已有能力。我们帮 Agent 做的是**训练并沉淀新的垂直能力**，并在后续调用中持续调用这项资产。这是传统 Skill 和练了么 Skill 在"能力来源"维度上的本质差异。
